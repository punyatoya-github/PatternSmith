# AI Craft Pattern Generator

Turn a photo into a printable craft pattern. **Phase 1 (MVP)** targets three crafts from one
shared engine: cross stitch, bead art, and an embroidery template.

> **Status: Weeks 1 to 2 complete, plus the Week 3 chart data.** The cross-stitch engine and CLI
> work end to end. There is no web UI, PDF export, bead or embroidery module yet.
> See [Roadmap](#roadmap).

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

python scripts/make_test_images.py            # synthetic images (no photos needed)
python -m app.cli data/test_images/synthetic/sunflower.png --level 3 --out pattern.png
```

CLI options:

```
python -m app.cli PHOTO [--level 1-5] [--width N] [--colors N] [--fabric-count 11|14|16|18]
                        [--strands 1-6] [--crop L,T,R,B] [--out pattern.png] [--json out.json]
                        [--cell 12] [--no-symbols]
```

`--level` is the complexity slider (1 = 40 stitches wide, 8 colors; 5 = 200 wide, 40 colors).
`--width` and `--colors` override the level. `--crop` takes fractions, e.g. `0.1,0.1,0.9,0.8`.

Example output:

```
Pattern: 100 x 100 stitches, 16 colors
Finished size on 14-count: 18.1 x 18.1 cm (7.1 x 7.1 in)
Generated in 0.14s -> pattern.png

Sym DMC      Stitches  Skeins  Name
A   3755         2963       2  Baby Blue
...
```

## How it works

1. **Load and validate.** PNG, JPG and WebP only. Size and pixel limits, EXIF orientation applied,
   transparency flattened onto white, metadata dropped.
2. **Crop and downsample** to one pixel per stitch (area interpolation).
3. **Cluster** the distinct colors with k-means in CIELAB, weighted by pixel count.
4. **Match to real DMC threads** with CIEDE2000, merge clusters that land on the same thread,
   then re-assign every pixel to the nearest *chosen* thread.
5. **Assemble** a grid of palette indices, most-used thread first, with a unique symbol per thread.
6. **Derive everything else** from that grid: preview image, stitch counts, finished size and an
   approximate skein estimate.

The pattern is stored as data (a grid plus palette), never as an image, so the preview, the future
PDF and saved projects all come from one source of truth. See [docs/decisions.md](docs/decisions.md).

## Development

```bash
ruff check . && ruff format --check .
pytest --cov=app
python scripts/benchmark.py        # fails if the engine exceeds its time budget
```

CI (`.github/workflows/ci.yml`) runs lint, format check, tests and the benchmark.

Current benchmark on the synthetic set (engine + preview): typical 100 x 100 about 0.3 s, 200 x 200
about 1.9 s, worst case (random noise at max settings) about 3 s.

## Known limitations

- **No cleanup yet.** Gradients and photos produce scattered single stitches at color boundaries
  (visible in the sample). Basic cleanup is Week 4.
- **Tested on synthetic images only.** Add real photos to `data/test_images/` and review them
  before trusting the presets (level to width/colors mapping).
- **Skein estimate is a heuristic** (full stitches only, fixed waste factor). Calibrate it against a
  published thread calculator before showing it to users.
- Thread colors are on-screen approximations. Buy by the DMC code, not by how it looks on screen.
